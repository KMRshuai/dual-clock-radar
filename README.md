# 双时钟风险雷达

基于"技术-市场双时钟错配"模型的经营风险监测工具，通过量化技术变化速度与商业兑现速度之间的差距，评估企业面临的经营风险。

## 核心模型

### 指标体系

| 指标 | 全称 | 含义 |
|------|------|------|
| **TCS** | Technology Clock Score | 技术时钟分数，衡量重大技术变化推向客户的速度 |
| **MCS** | Market Clock Score | 市场时钟分数，衡量技术商业化兑现的速度 |
| **DMI** | Dual-clock Mismatch Index | 双时钟差，DMI = TCS - MCS |
| **E** | Exposure Factor | 风险暴露系数，综合客户、版本、财务、合规、技术五个维度 |
| **RMI** | Risk Mismatch Index | 风险错配指数，RMI = |DMI| x (1+E)，上限 100 |

### 四色预警

| 等级 | RMI 范围 | 响应措施 |
|------|----------|----------|
| 绿色 | < 20 | 正常监测 |
| 黄色 | 20 - 40 | 检查重点客户和版本变化 |
| 橙色 | 40 - 60 | 启动跨部门干预 |
| 红色 | >= 60 | 纳入经营层专项管理 |

### TCS 子项（权重）

- 有效版本迭代频率 (0.25)
- 核心功能变化强度 (0.25)
- 接口非兼容变化率 (0.20)
- 模型及依赖变化率 (0.15)
- 并行版本负荷 (0.15)

### MCS 子项（权重）

- PoC 验证速度 (0.20)
- 采购决策速度 (0.20)
- 合规审查速度 (0.20)
- 交付验收速度 (0.20)
- 商业兑现速度 (0.20)

### E 子项（权重）

- 客户集中暴露 (0.25)
- 版本兼容暴露 (0.25)
- 财务暴露 (0.20)
- 合规暴露 (0.20)
- 技术依赖暴露 (0.10)

## 四个部门视角

- **管理层**：经营风险总览，跨部门全局视图
- **销售交付**：客户转化漏斗风险、交付延期指数、客户流失预警
- **研发**：技术债务指数、版本碎片化、API 稳定性、研发效能影响链
- **财务合规**：现金流压力、合规缺口、收入确认风险、现金流影响时间线

## 本地运行

无需任何构建工具，直接用浏览器打开 `index.html` 即可。

```bash
# 或者用任意静态服务器
npx serve deploy/
python -m http.server 8000 --directory deploy/
```

## GitHub Pages 部署

1. Fork 或克隆本仓库
2. 进入仓库 Settings -> Pages
3. Source 选择 **Deploy from a branch**
4. Branch 选择 **main**，文件夹选择 **/ (root)**
5. 保存后等待构建完成，访问 `https://<username>.github.io/<repo-name>/`

## 项目结构

```
deploy/
  index.html        # HTML 结构
  css/style.css     # 样式（含深色主题）
  js/app.js         # 计算逻辑与仪表盘渲染
  README.md         # 项目说明
```

## 预设案例

内置四组预设数据，方便快速体验：

- **论文企业 A（治理前）**：技术时钟快、市场时钟慢，典型高风险场景
- **论文企业 A（治理后）**：治理后双时钟差收窄，风险回落
- **Stability AI**：极端错配案例，技术极快、市场极慢
- **健康企业**：双时钟基本同步，风险可控
